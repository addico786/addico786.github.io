# SEO Implementation Plan — adnankhan.tech

Same four phases as the Archipillar plan, aimed at freelance client acquisition
rather than a construction firm. Phase 1 is done; Phases 2–4 are on you.

The difference that matters: Archipillar was a **local business** — one city,
walk-in trade, Google Business Profile is the whole game. You are a **remote
service provider**. Local intent still helps ("web developer in Delhi" has low
competition and real buyer intent), but most of your leads will come from
service and problem keywords, not proximity. Phase 2 is weighted accordingly.

Schema note: the template specified `LocalBusiness` / `GeneralContractor`.
`ProfessionalService` is the correct type here — it is a `LocalBusiness`
subtype, so it keeps the local signals (address, `areaServed`) while describing
a service practice rather than a contractor with a yard.

### AEO / GEO — added August 2026

Two acronyms doing the rounds. **AEO** (answer engine optimisation) is about
winning the answer box; **GEO** (generative engine optimisation) is about being
the source cited *inside* a generated answer. In practice they ask for the same
four things, and all four are now in place:

| Signal | Where it lives |
| --- | --- |
| One resolvable entity, not three loose objects | `@graph` with stable `@id`s in `layout.tsx` |
| Declared expertise | `knowsAbout` on the `Person` node |
| Named service area, not "Worldwide" | `areaServed`: Delhi, Delhi NCR, India |
| Extractable answers with real numbers | `site.faqs` → visible FAQ **and** `FAQPage` schema |

The rest of it — GBP, reviews, NAP consistency — is off-site and is Phase 2.
That is deliberate: for local AI answers, the Business Profile now carries more
weight than the website does.

**Everything above regenerates from `src/data/site.ts`.** Add a service and it
enters the `OfferCatalog` automatically. Nothing is hand-maintained.

## Phase 2 — Visibility (Weeks 1–4)

Do these in order. The first two are worth more than everything else combined.

1. **Google Search Console** — verify by DNS (Domain property, not URL prefix),
   submit `sitemap.xml`, request indexing for `/`.
2. **Google Business Profile** — category "Website Designer", service area
   Delhi NCR + "online". Free, and it is what wins "web developer near me".
3. **NAP consistency** — name, address area, and email identical everywhere.
   Right now `adnankhan.tech` says `hello@adnankhan.tech` and your old site
   says `adnandelhi2004@gmail.com`. **Pick one.** Inconsistent contact details
   split your entity signal.
4. **Profiles that rank for your name** — GitHub, LinkedIn, X, Instagram,
   Behance if you use it. All are in the JSON-LD `sameAs` already, which tells
   Google they are the same person. Make sure each links back.
5. **Directories** — Clutch, Upwork, Fiverr, IndiaMART. Lower quality than the
   above, but they rank for "hire web developer Delhi" and you can too.

## Phase 3 — Content (Month 2 onward)

**One page cannot rank for more than one thing.** You currently have one page.
This is the phase that actually moves you, and it is the phase you have not
started.

### Service pages — one per service, one URL each

```
/services/web-development
/services/seo
/services/automation
/services/cloud-devops
```

Each needs: the problem in the client's words, what you deliver, what it costs
(a range beats silence), how long it takes, and one piece of proof. 600–900
words. Link each from the services list on the home page.

### Location pages — only where you would actually take the work

```
/web-development-delhi
/seo-services-delhi
```

Do not spin up twenty city pages. Two real ones beat twenty thin ones, and thin
location pages are exactly what Google's spam policy targets.

### Case studies — one per month, from work you have already done

You have six projects with nothing written about them. Each is a case study:
the problem, what you built, what changed. `/work/flint`, `/work/vibescan`,
`/work/urban-tech-buildings`. These rank for long-tail terms and they are the
thing a prospective client actually reads before emailing you.

### Keyword themes

| Intent | Terms |
| --- | --- |
| Hire | freelance web developer india, hire nextjs developer, freelance seo consultant delhi |
| Service | technical seo audit, core web vitals optimization, n8n automation consultant |
| Stack | nextjs developer for hire, cloudflare pages developer, terraform freelancer |
| Problem | why is my website slow, site not ranking on google, automate repetitive tasks |

The problem column is where seomachine earns its place — those are blog posts,
and that repo exists to write them at volume once `/blog` exists.

### Blog — done (August 2026)

`/blog` exists, with three buyer-stage posts. Topics were chosen against 2026
search behaviour rather than volume: pricing (where every competing page is an
agency with a reason to quote high), AI-search visibility, and agent-readable
markup. See `CONTEXT.md` for how the route works and `SEO-SETUP.md` for the
Search Console steps.

One caution, since the Blog Engine makes volume cheap: **do not publish at
volume.** Six to ten real posts, one every week or two, human-edited. Thin
AI-generated content on a new section is exactly what Google's helpful-content
system targets, and it drags the whole domain — not just the thin pages.

## Phase 4 — Measurement

- **Search Console** — check weekly. Sort Performance by **impressions**, not
  clicks. Queries with impressions and no clicks are pages you should write.
- **GA4** — track: email click, X/Instagram click, project row expand, CTA
  click. Without these you cannot tell traffic from leads.
- **Expectations** — 3–6 months for organic. A new domain path on an existing
  domain helps; `adnankhan.tech` already has history, which is an advantage
  over a fresh domain.
- **Bridge** — Google Ads on "freelance web developer delhi" while organic
  builds, if you want leads before month three.

## Core Web Vitals

Measured on the live production build — see the results printed by the audit in
the session, and re-measure with PageSpeed Insights after any content change.
Targets from the template: LCP < 2.5s, INP < 200ms, CLS < 0.1.

The hero photograph is the LCP element. If LCP is slow, that image is the
first thing to compress — it ships at 767×742 PNG and would be markedly
smaller as WebP.
